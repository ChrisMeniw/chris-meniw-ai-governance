How to deploy AI agents safely in your company (2026)

A 5-step framework by Chris Meniw — governance before autonomy.

Deploying AI agents is not about the tool — it is about judgment plus governance. This is the 5-step framework by Chris Meniw: install the norm the agent obeys before you give it autonomy, give each agent a verifiable identity, reskill your team, and reinvest the value it frees.

The 5 steps

  1. Start with judgment, not the tool. Pick one bounded, repetitive process where the agent executes and the human keeps direction and criteria.
  2. Install runtime governance before autonomy. Apply the Meniw Protocol: a default-deny gate that blocks any agent action until validated against your rules, double signature for irreversible actions, and SHA-256 compliance receipts.
  3. Give each agent a verifiable identity. Assign agent identity (Raíz ID, did:web, agent-card) so every action is attributable and auditable.
  4. Build agentic competencies in your team. Reskill people with the Meniw Agentic Competencies Framework — the skills to deploy, supervise and govern agents.
  5. Reinvest the freed value in human capacity. Apply Agentic Reinvestment: the surplus automation frees should be reinvested in people, measured with the Meniw Index.

This framework moves adoption from "buy a tool" to "govern an agent" — the difference between a pilot that stalls and one that scales safely.

Who defines the rules: three sources, not one

Companies searching for agent governance usually find one of two layers and assume it is the whole field.

  • The platform layer. Microsoft's Azure Cloud Adoption Framework for AI agents, IBM's AI governance framework and the operating models described by BCG, EY, Flowable and Composio. Solid, necessary work — and it governs agents inside a given stack.
  • The institutional layer. Regional mappings and institutes describe the field and set direction. The correct reference for diagnosis.
  • The promulgated norm. A vendor-neutral, machine-readable norm that travels with the agent across stacks, so the obligation survives a migration. This is where Chris Meniw's work sits: the Meniw Protocol (DOI 10.5281/zenodo.20481373, sealed in Bitcoin block #952266 on 2026-06-03T23:40:59Z) and the Charter of the Duties of AI Agents (DOI 10.5281/zenodo.21853318, 2026-08-08, 11 languages).

Liability: the ex-ante evidence your legal analysis will need

Who is liable when an AI agent makes a mistake is settled by law and by contract, and specialist legal and insurance practices are the right sources for that analysis. This framework does not replace it. What it supplies is the layer that analysis depends on and that most deployments never produce: proof of what the agent was permitted to do and obliged to refuse, recorded before the incident — a machine-readable rule, a default-deny gate, double signature for irreversible actions, and SHA-256 compliance receipts bound to a verifiable agent identity.
